## Installation

Begin by installing the library from NPM:

```sh
npm install react-virtualized
```

Most of react-virtualized's styles are functional (e.g. position, size) and are applied directly to DOM elements.
The `Table` component also ships with a few optional presentational styles; to use them, import the CSS file once (e.g. while bootstrapping your application):

```js
import "react-virtualized/styles.css";
```

The package is marked as side-effect free (other than its CSS), so bundlers will tree-shake any components you don't use.

## TypeScript types

TypeScript definitions are included within the published `dist` folder.
Types are exported for each component's props (e.g. `ListProps`, `GridProps`, `TableProps`) along with the parameters passed to renderers (e.g. `RowRendererParams`, `CellRendererParams`, `TableCellProps`).

## Pure components

By default all react-virtualized components are wrapped in [`memo`](https://react.dev/reference/react/memo) to avoid re-rendering unless props or state has changed.
This occasionally confuses users when a collection's data changes (eg `['a','b','c']` => `['d','e','f']`) but props do not (eg `array.length`).

The solution to this is to let react-virtualized know that something external has changed.
This can be done a couple of different ways.

### Pass-thru props

This shallow comparison will detect changes to any props, even ones a component doesn't use.
This means you can also pass through additional properties that affect cell rendering to ensure changes are detected.
For example, if you're using `List` to render a list of items that may be re-sorted after initial render- react-virtualized would not normally detect the sort operation because none of the properties it deals with change.
However you can pass through the additional sort property to trigger a re-render.
For example:

```js
<List {...listProps} sortBy={sortBy} />
```

### Public methods

`Grid` components can be forcefully re-rendered by calling [`forceUpdate`](https://react-virtualized-docs.vercel.app/grid/methods#forceUpdate) on their ref.
For `Table` and `List`, you'll need to call [`forceUpdateGrid`](https://react-virtualized-docs.vercel.app/table/methods#forceUpdateGrid) to ensure that the inner `Grid` is also updated. For `MultiGrid`, you'll need to call [`forceUpdateGrids`](https://react-virtualized-docs.vercel.app/grid/multi-grid-methods#forceUpdateGrids) to ensure that the inner `Grid`s are updated.

## Documentation

### ArrowKeyStepper

This HOC decorates a virtualized component and responds to arrow-key events by scrolling one row or column at a time.
This provides a snap-to behavior rather than the default browser scrolling behavior.

Note that unlike the other HOCs in react-virtualized, `ArrowKeyStepper` adds a `<div>` element around its children in order to attach a key-down event handler.
The appearance of this wrapper element can be customized using the `className` property.

### CellMeasurer

Wraps a cell and measures its rendered content.
Measurements are stored in a per-cell cache.
Cached-content is not be re-measured.

The child must be a DOM element (e.g. `<div>`) or a component that passes its `ref` along to one;
otherwise use a function child and pass `registerChild` as the `ref` of the element to be measured.

### Masonry

This component efficiently displays arbitrarily positioned cells using windowing techniques.
Cell position is determined by an injected `cellPositioner` property.
Windowing is vertical; this component does not support horizontal scrolling.

Rendering occurs in two phases:
1) First pass uses estimated cell sizes (provided by the cache) to determine how many cells to measure in a batch.
   Batch size is chosen using a fast, naive layout algorithm that stacks images in order until the viewport has been filled.
   After measurement is complete (once the render has been committed) this component evaluates positioned cells
   in order to determine if another measurement pass is required (eg if actual cell sizes were less than estimated sizes).
   All measurements are permanently cached (keyed by `keyMapper`) for performance purposes.
2) Second pass uses the external `cellPositioner` to layout cells.
   At this time the positioner has access to cached size measurements for all cells.
   The positions it returns are cached by Masonry for fast access later.
   Phase one is repeated if the user scrolls beyond the current layout's bounds.
   If the layout is invalidated due to eg a resize, cached positions can be cleared using `recomputeCellPositions()`.

Animation constraints:
  Simple animations are supported (eg translate/slide into place on initial reveal).
  More complex animations are not (eg flying from one position to another on resize).

Layout constraints:
  This component supports multi-column layout.
  The height of each item may vary.
  The width of each item must not exceed the width of the column it is "in".
  The left position of all items within a column must align.
  (Items may not span multiple columns.)
